- **Tests**: 42-test pytest suite (no network) covering field mapping and normalisation, ArcGIS pagination, geocode caching/failure handling, Europe/Dublin DST duration maths, hash-based inference skipping, and the work_type backfill. CI runs `pytest` instead of `py_compile`.
- **Pipeline hardening**:
  - HTTP retry adapter (backoff on 429/5xx, honours Retry-After) on all sessions
  - stable ArcGIS pagination via `orderByFields=OBJECTID`
  - geocode failures write retryable placeholder rows instead of failing the FK later; circuit breaker fails the build after 10 consecutive failures (service down)
  - `''` from the feed normalised to `NULL`
- **work_type backfill**: filled from title categories whose feed labels are ≥95% one-sided with ≥20 labelled cases (coverage 31% → 68%); ambiguous categories deliberately stay NULL
- **Inference**: identical descriptions (multi-pin events) inferred once per run (~15% fewer LLM calls); LLM timeout raised 15s → 120s
- README rewritten for outside users; new data-quality findings documented in `notes/`

## PR #15 — Add work_category and derive work_type from title categories
*merged 2026-07-11 · +519/−73*

### PR body

## Summary

Adds a `work_category` column and a single title-category rule mechanism that both categorises cases and fills in `work_type` where the title makes the answer unambiguous.

### The mechanism
`CATEGORY_RULES` in `src/uisce/pipeline.py` normalises each title's category part (`"Category – County"`, with messy hyphen/en-dash/spacing) into a stable slug and attaches one `work_type` policy:

- **`"Planned"` / `"Unplanned"`** — set on every match, *overriding the feed*, where the label is editorially unambiguous (a burst main is never planned; installation/rehabilitation/new-connection works are always planned; the stray contradicting rows are typically the completion update at the end of a job).
- **`None`** — slug only, `work_type` left exactly as the feed reported it. Used for `mains_repair` and `power_outage`, which genuinely occur both planned and unplanned with no title-level signal to separate them.

**26 categories** as of the 2026-07 snapshot. `work_type` coverage rises from the feed's ~31% to **~89%**; only 29 cases end up with no `work_category`, and they're genuinely one-off titles.

`work_category` is a deterministic normalisation of an existing column, so it lives in `cases` (not `inferred_cases`), added via an idempotent `ALTER TABLE` since the published DB is downloaded and updated in place each build.

### Also included
- **Title trimming** on load, plus a DB cleanup for legacy untrimmed rows.
- **`uisce-pipeline --skip-geocode`** — refresh cases from ArcGIS without spending LocationIQ calls; new coordinates get placeholder geocode rows (retried on the next real run).
- **`uisce-backfill`** — standalone command to re-derive the computed columns on an existing `uisce.db` with no network, for iterating on category rules.

## Testing
- 56 tests pass, ruff clean.
- Rule table guarded by structural invariants (no duplicate variants or slugs, variants pre-normalised, every rule reachable via `classify_category`).
- Verified against a copy of the real DB: every category maps to a single `work_type` except the two intentional slug-only ones; coverage 89%.
