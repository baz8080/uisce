## What happened

`uv run uisce-infer` failed on case 243245 with an opaque parse error:

```
Failed case 243245: Unterminated string starting at: line 1 column 307 (char 306)
0 cases answered by rules-v1, 0 by gemma-4-12b-qat
```

The case is a 4,448 character boil water notice. With `gemma-4-12b-qat` loaded at a 4,096 token context, prompt plus notice came to 4,018 tokens, leaving 78 for the answer. The model stopped mid-string with `finish_reason: length`:

```
{"notes":"...no usable end-time signal was found.","end_source":"not_found","local_date":null,"local_
```

`json.loads` then reported `Unterminated string`, which reads like the model gave a bad answer rather than a truncated one. That misdirection is what made it hard to place. The context was the whole cause: all 49 descriptions over 3,000 chars, up to 5,093, extracted cleanly under the same prompt v3 on 2026-08-02.

## What changed

Two things the failure exposed, both in `src/uisce/inference.py`:

1. **`call_llm` ignored `finish_reason`.** It now checks it and raises with the token counts and the remedy, so a short context names itself:

   ```
   Failed case 243245: response truncated: the model stopped after 78 tokens with 4018 of prompt. Raise the context length gemma-4-12b-qat is loaded with in LM Studio.
   ```

2. **`run()` swallowed the failure whole.** No record written, summary reading `0 by rules, 0 by gemma`, exit 0. A run that extracted nothing looked identical to a run with nothing to do, and CI's `--rules-only` build would have gone green over a dropped case. Failures are now counted, printed in the summary, and returned as a non-zero exit. The console script wrapper turns that into the process exit code.

Four tests added in `tests/test_inference.py`: `call_llm` passing content through on a clean stop and raising on truncation, and `run()` reporting a failure with exit 1 while a clean run still exits 0.

## For the reviewer

**The HTML is deliberately left alone.** The `<br><br>\n\n` scaffolding in these notices is a large share of those 4,018 tokens and stripping it would have made the case fit. But it changes what the model reads, and per CLAUDE.md that is a methodology change to be measured, not folded into a bug fix.

The underlying case is already extracted and committed on `main` (496f7a1) after the model was reloaded at an 8,192 token context, which clears the corpus's 5,093 character worst case with margin. This PR is the code half only.

## PR #75 — Fix category classification for dash-separated titles
*merged 2026-09-03 · +32/−5*

### PR body

## Summary

Fixes category classification for water disruption notices where the title uses a dash with inconsistent spacing (e.g., "Mains Repair Works -Meath" with space before but not after the dash). Also adds two missing category variants that were causing misclassifications.

## Changes

- **Updated title-to-category splitter regex** (`_TITLE_CATEGORY_SPLIT`): Changed from `r"\s*[–-]\s+"` to `r"\s+[–-]\s*|\s*[–-]\s+"` to accept whitespace on either side of the dash, not just after it. This fixes cases where the space appears before the dash with none after, which previously swallowed the county into the category key.

- **Preserved hyphenated word integrity**: The new pattern still requires at least one whitespace character adjacent to the dash, so dashes with no whitespace (like in "Mains Tie-In" and "Supply Re-direction") do not split. This maintains the invariant that keeps hyphenated words whole.

- **Added missing category variants**:
  - `"mains flushing works"` → `mains_flushing`
  - `"fire hydrant replacement"` → `hydrant_repair`

- **Added test coverage** for the new splitting behavior and the previously-failing cases.

## Implementation Details

The regex now matches two patterns:
1. `\s+[–-]\s*` — whitespace before the dash, optional after
2. `\s*[–-]\s+` — optional before the dash, whitespace after

This ensures that:
- "Mains Repair Works -Meath" splits correctly (space before, none after)
- "Burst Water Main - Cork" still splits (space on both sides)
- "Mains Tie-In - Cork" splits only at the spaced dash, leaving "Mains Tie-In" intact
- "Supply Re-direction" does not split at all (no whitespace around the hyphen)

All existing variants resolve to themselves under the new pattern, with no regressions.
