## PR #16 — Static status site with per-county disruption metrics, plus end-time eval
*merged 2026-07-18 · +21354/−4*

### PR body

## Summary

Turns the collected notice data into a statuspage-style static site, and puts a measured accuracy number on the LLM end-time extraction that everything downstream trusts.

- **`uisce-site`** (src/uisce/site.py + site.html) renders `out/uisce.db` into a fully static site in `out/site/`: per-county month view with day bars, population-weighted availability (SAIDI-style: Census 2022 Small Areas within 500 m of each pin, via the committed `data/sa_pop.csv` from `uisce-fetch-sa-pop`), A–F grades driven by hard outages only, boil-notice issue→lift pairing, and a median time-to-fix stat. Copy deliberately claims "announced disruptions + time-to-fix", not availability.
- **`first_seen`/`last_seen` stamps** in the pipeline (upsert preserves `first_seen`) as a tripwire for future feed pruning — a live-feed check confirmed nothing has been deleted since collection began.
- **Human eval of the end-time extraction**: stratified 114-case sample, fully labelled and scored. Raw accuracy 71.9%; 82.8% on the classes that feed durations (all 15 `lifted_immediate` misses were a labelling-convention disagreement, and that class stores NULL duration anyway). Error taxonomy and prompt-fix backlog in `notes/end-time-eval.md`. Eval rounds are one CSV each, named and stamped with the model and prompt version that produced the sampled outputs.
- **Notes**: methodology, SLA benchmark research (why Ofwat/CRU numbers can't be borrowed), population data sources, eval guide + results, and new data-quality findings.

## Test plan

- `uv run pytest` — 86 tests covering severity classification, grading, interval union/clipping, lift pairing, the Small Area index, `build_site` end-to-end cases, the seen-stamp upserts, and eval sampling/round naming
- `uv run ruff check .` — clean
- Site built and inspected locally against the 2026-07 snapshot; eval scored on the labelled round 1 CSV

## PR #17 — End-time prompt v2: validated, corpus re-inferred
*merged 2026-07-20 · +9757/−72*

### PR body

Ships prompt v2 for end-time extraction, validated against two eval rounds, plus the corpus re-inference under it. Also settles the boil-notice policy that round 1 kept tripping over.

## Results

Round 1 identified three failure modes. pv2 targets all three and closes all three.

**Replay** — pv2 re-run over round 1's 114 labelled rows, scored against the same human labels. A regression filter, not an accuracy estimate: these are the rows pv2 was reasoned from.

| prompt | overall | excl. `lifted_immediate` |
|---|---|---|
| pv1 | 81/114 = 71.1% | 81/99 = 81.8% |
| pv2 | 99/114 = 86.8% | 99/99 = 100% |

**Round 2 — 120 unseen cases, uniform draw: 120/120.** This is the first unbiased corpus-wide estimate the project has produced. It is *not* comparable to round 1's published 71.9%, which oversamples minority classes by design.

Read the 100% as "no errors detectable at n=120", not as perfect: with zero errors the 95% lower bound is ~97.5%, so the sample cannot separate a 99.9% prompt from a 97.6% one. Two classes drew zero rows and are unmeasured; 67% of the sample is `completion_update`, which is the corpus mix but makes the headline largely a claim about that class.

## Corpus re-inference

7,892 cases, zero failures. About 1.5% changed class, all in predicted directions:

| end_source | pv1 | pv2 | Δ |
|---|---|---|---|
| completion_update | 4,616 | 4,715 | +99 |
| scheduled_end_with_time | 2,543 | 2,503 | −40 |
| scheduled_end_date_only | 55 | **0** | −55 |
| not_found | 296 | 291 | −5 |
| lifted_immediate | 42 | 43 | +1 |

`scheduled_end_date_only` is now unreachable, so every `scheduled_end_with_time` and `completion_update` case was checked for whether its description contains a time at all. **No fabrications.** The 15 apparent exceptions were real: 12 say "midday", 3 are Irish-language notices ("10rn go dtí 6in") converted correctly by the prompt's Irish rules.

## Also in here

- **Boil-notice policy consolidated.** Boil notices cannot end themselves — the lift is published as a separate case — so `end_source` is `not_found` for all of them and no prompt version changes that. `lifted_immediate` is excluded from site metrics rather than modelled: 42 pins deduping to 15 events, of which the description-derived approach would rescue one. Reasoning in `notes/boil-notices.md`.
- **`uisce-eval-sample-fresh`** — draws N unseen cases and infers only those, so a fresh round costs ~120 calls instead of a 7,892-call corpus run. Trades stratification for a uniform draw; rationale in `notes/end-time-eval.md`.
- **Skip-logic fix** — `get_cases_needing_inference` now compares `prompt_version` as well as description hash, so a version bump actually re-infers. Previously a bump re-inferred nothing.
- **Replay harness fix** — `truth_for()` fell back to the model's value for `end_source` on blank cells but not for date or time, so partially-corrected rows carried an unmatchable empty-string truth and understated every prompt equally.

## Reviewer notes

**Two things worth deliberate attention:**

1. **Round 1's CSV is modified** (14 lines), which breaks the "round files are never overwritten" rule stated in `notes/end-time-eval.md`. Four rows had defective ground truth: a correction written only in `human_notes`, a swapped date/time pair, a row endorsed `correct` whose blank time the description contradicts, and one where the labeller revised their own answer on review. Judgement is unchanged in all four; only transcription was fixed, and each carries an `[amended 2026-07-19: ...]` marker. Taken because the file is the measuring instrument for every future prompt and the defects cost ~4 points on any version scored against it.
2. **`data/inferred_duration.jsonl` grows by 7,892 lines.** pv1 records are deliberately retained: the file is the only corpus-wide record of pv1's output, and the pv1↔pv2 comparison above is only computable because both coexist.

Two findings were parked rather than acted on, recorded in `notes/data-quality.md`: `start_date` is a publication timestamp rather than an event start (sharpens and partly corrects an existing section), and reference-number pairing for "we are investigating" notices works but rescues 2 of 203 cases.

`uisce-build-inferred` is intentionally **not** run here — CI builds three times a week.
