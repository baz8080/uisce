## PR #37 — Publish a landing page per county, and report analytics from them
*merged 2026-08-06 · +685/−33*

### PR body

## Why

The site was **two indexable URLs**: `index.html` and `areas.html`. Everything a reader might search for — a county, a town — lived behind a hash route (`#county/Cork`), which is not a URL a search engine can index, and the content itself only existed inside `data.js` and the history shards. Someone googling "water outage Cork" had nothing to land on.

This came out of asking whether a custom domain would help SEO. It wouldn't, much: `github.io` is on the Public Suffix List, so the site is already treated as its own property with no shared-authority penalty. The page surface was the ceiling, and raising it costs nothing.

## What

**26 server-rendered county pages** at `c/<county>.html`, carrying the same figures the app charts — summary and current grade, open notices, the month table, the notice history, and every area with its notice count. No `data.js` and no shard on these pages; the interactive view stays one link away rather than being reproduced.

Plus the discovery files the site never had: `sitemap.xml`, `robots.txt`, and a self-referential canonical on every page. `BASE_URL` in `config.py` is the single point of change if the site ever moves off `github.io` — which it cannot 301 away from.

| | before | after |
|---|---|---|
| Indexable URLs | 2 | 28 |
| Static text across the site | 73,087 chars | 383,714 chars |
| Pages reporting to analytics | 1 | 28 |

## Analytics: what #25 was actually up against

#25 added `history.pushState` to `go()` so Cloudflare Web Analytics would count a county drill-down as a page view. It does not do that, and no variation on that call would: what it pushes is a **fragment**, so the path stays `/uisce/` for the whole session and a beacon that counts views by path has no new page to report. Real documents at their own URLs are what fixes it.

The `pushState` stays — with the `popstate` listener it is what makes the back and forward buttons work across drill-downs, a second and real job the original description didn't claim. The comment now says what it achieves rather than what was hoped.

The beacon also went onto `areas.html`, which never had it despite being the largest single page on the site.

## Two bugs fixed on the way

- The directory's search selects a whole county by matching its heading, and the heading now also carries the county-page link — so searching "page" would have selected all 26 counties. The bare name moved to `data-county`.
- Grade **C** rendered white-on-amber: `td.g` is a more specific selector than `.g-C`. (`site.html` reaches for `!important` here; this uses `td.g-C`.)

## Verification

`ruff` clean, **339 tests pass** (14 new). A real build against the local DB produces 28 pages, a sitemap of 28 unique URLs, no leaked template markers, and exactly one correct canonical per page.

Checked in-browser at desktop and mobile, light and dark: no console errors, county pages make **one** request each before the beacon (no `data.js`, no shard), the page never scrolls sideways, and the wide month table scrolls inside its own box.

Note: county pages now make one external request (the beacon) where they otherwise would make zero — the trade for having them report at all.
